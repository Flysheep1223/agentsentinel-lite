# 早期task预测改进：离线开发方案

制定日期：2026-11-06。用户要求执行早期漏判/误停分析，并继续使用LR尝试改进。
本方案固定于新模型拟合前，独立输出目录为`artifacts/early_lr_v1`。
这是已经查看过v2验证结果后的开发实验，不是新的独立测试。

## 先验诊断与问题

v2验证集1176条Session，997成功、179失败。第3步按0.5分类时漏掉155次失败：
其中75次当时没有工具错误，80次已有错误；155次均尚无写入、尚无历史写入违规。
同一步被正确识别的24次失败全部已有错误。成功任务中也有313次已有错误。
因此累计错误不能作为可靠的单一失败判定。

v2风险政策`risk@0.01`误停5条原成功轨迹，全部为incident：

- `6e9155e35ee04edb868cac64cb44448b`：第9步停止；第11/12步才写入并成功。
- `725434a558b94318ad540e8f18ea7be1`：第8步停止；第10/11步写入并成功。
- `8e1e18979ab74254be1073e9474564b1`：第10步停止；第11/12步写入并成功。
- `c04cac5bfdd44f3293f3ce085a99b1d4`：第9步停止；第10/11步写入并成功。
- `fe8a8ea1857249ff974eeef0d10cb6a6`：第9步停止；第11/12步写入并成功。

其中部分返回status=ok但lookup_policy缺少action，后续重读才返回该字段；
现有22列特征没有描述返回字段完整性、跨步骤恢复和全局同参调用状态。
字段完整性来自工具实际返回和公开工具契约，不使用故障注入器的标签或配置。

仅按工作流和前三步tool/status序列分组，训练3542条中3378条、
验证1176条中1098条处于包含两种最终结果的组。
这说明这些粗粒度模式并不唯一决定结局，不能据此证明所有运行时信息均无预测价值。
新方案不承诺一定能显著提前预测；如仍无改善，如实保留负结果。

## 数据和安全边界

主标签保持`task_success=1-原label`，同一Session的全部前缀共享原最终结果。
只使用原train/validation，保留父家族分区与三折CV，不读取新的test预测或用test选策。
以v2的封印目标、预测和原始轨迹哈希为输入；读取原始trajectory前后验证SHA256。
重新构建的旧22列必须与v2前缀逐行一致，再加入新增特征。
原始数据、v1/v2及第二轮的源码、模型、封印文件不修改；仅新增模块和独立产物。
输出目录存在则拒绝覆盖；新增收费请求0，不加载真实API配置。

运行时只接收投影后的可观察工具事件：
step、tool、arguments、response、status、error、schema_error、is_write、
latency_ms、elapsed_ms和累计用量totals。totals再限制为原特征实际使用的Token和费用字段。
task/template/session ID、故障配置、fault/kind、标准答案、验证器信息、未来事件不能进入模型。
arguments只用于相等性和计数；模型不接收原始ID、字段值、正文或原始response文本。
response仅检查公开读取接口的字段存在和非空，不使用任务标准答案或最终状态。

## 固定候选特征

所有候选保留原22列，不改变旧提取器。新增特征由每Session独立的因果流式提取器生成；
所有累计量只使用当步及此前事件，步数连续，未来事件改变不能影响已生成的前缀。

history组：

- 不同工具数、不同tool+arguments调用数、当前同参调用累计次数、全程同参重复比例。
- 连续读取步数、距离最近成功写入的步数（尚无成功写入时等于当前步数）。
- 发生错误后尚未成功重试的调用种类数、曾成功恢复的调用种类数。
- 已经成功读取后再次读取的次数、工具切换比例。
- 最近5步错误比例、最近5步同参重复比例。
- 当步Token增量、最近3步Token增量均值（缺失保持缺失）。
- 当前步数×累计错误比例、当前步数×全程同参重复比例。
- 最近3步工具序列、最近3步状态序列、最近3步同参调用的相等模式。

payload组：

- 当前读取返回缺失字段数、累计不完整读取次数、连续不完整读取次数。
- 仍未获得完整返回的同参读取种类数、曾从不完整返回恢复的读取种类数。
- 已成功取得完整返回的不同读取调用数、截至当步的完整读取比例。
- 公开最小字段：get_ticket=[ticket_id,service_id]；
  get_service_status=[service_id,state]；lookup_policy=[service_id,action,owner]。
  读取错误本身也算未得到完整读取返回；写操作不按上述读取契约检查。

共四个新拟合变体：

1. control22：仅原22列，按本轮早期CV目标重新选LR参数。
2. history：原22列+history组。
3. history_payload：原22列+history组+payload组。
4. history_payload_early：与history_payload相同，拟合时第1～6步原始权重为2，其余为1。

另以冻结v2主LR和其已保存的训练OOF/验证预测为对照，不重训v2。
辅助当前验收LR、剩余CNY和Token的Ridge保持v2模型，不能把辅助真实标签加入主输入。
不增加其他模型类型，不根据本次验证成绩追加候选特征或参数。

## 训练与模型选择

LR候选C=[0.1,1,10]，class_weight=[None,balanced]，
max_iter=2000、random_state=42；数值线程1。
沿用数值插补、缺失指示、标准化和类别One-Hot，全部在拟合折内学习。
每Session最多等距6个拟合前缀；每Session权重和相同，再归一化整体行权重均值为1。
early变体先给早期行乘2，再在每Session内归一化，不能让长Session获得更高总权重。

每个候选在原父家族三折上拟合；在留出折的全部前缀保存OOF预测。
主选参指标为三折平均的“第3步Brier与第6步Brier的均值”，各时点保留实际存活分母。
同分按枚举顺序。全前缀Session等权Brier作为次要诊断，不使用验证标签选模型。
在冻结v2与四个新变体中，按同一训练OOF早期Brier选择主模型；并列优先v2、再候选顺序。
单类拟合显式常量，缺失必要评价时点则拒绝静默换分折。

## 停止政策与评价

默认仍只预测，不启用完成停止。可选风险停止只依赖主最终成功概率；
保持预测剩余资源≥0的门槛，费用头不可用时不自动停止。
固定连续两步确认，成功概率阈值为关闭、0.01、0.025、0.05、0.10、0.20、0.30、0.40、0.50。
步数间隔重置连续证据；每Session最多停止一次，第12步不产生新决策。

政策选择改用**训练OOF预测**，预算为0%和1%原成功误停率。
按执行CNY最少选取；任一所需成本缺失则全局用Token；
再依次比较误停少、捕获原失败多、总停止少、枚举早。
误停以原成功Session为分母，与停止时验收是否已通过无关；挽救数不能抵扣。
模型和政策统一在看本轮新验证预测前冻结，验证上不再重选。
训练OOF预算不保证验证达标，需明确报告验证中是否满足1%。

评价保存：

- 各候选训练CV和验证全前缀、固定第1/3/6/9/11步、共同第3/6/9步Session的
  Brier、AUC、两类AP、Log loss、ECE、0.5阈值混淆矩阵与召回。
- 父家族/模板/工作流/条件分组，列明Session分母；不把样本数当独立家族数。
- 同一90%/80%失败概率门槛下，v2与新模型的停止数、平均/中位停止步、
  判失败准确率、失败覆盖率、成功任务误停率、严格验收成功损失、费用/Token节省。
- 全部固定门槛曲线（名称使用“触发停止task数”和“成功任务误停率”）。
- 训练OOF选中政策的验证结果，和历史v2验证选策分开标识。
- 第3/6步前累计失败告警及首次违规前告警，避免只用接近终点的告警声称早期改善。
- 5个原误停实例和155个早期漏判的前后变化、归因和完整逐步预测表。
- 所有费用节省仅为原轨迹回放，不包含监测器开销，不推断实际线上收益。
