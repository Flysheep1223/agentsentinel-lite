## 2. 本轮验证

- 自动化回归：**104项测试通过**。覆盖40实例正常完成、实际依赖读取路径、标签与终止原因分离、最后允许调用的告警资格、违规写记录、分区不变、设计防篡改、固定CV折及30/600/160采集协议。
- 静态检查：`ruff check src tests` 通过；`git diff --check` 通过。
- 脚本正常行为验证：40/40实例完成，正常路径最多8次工具调用；固定单次瞬态故障的工程验证覆盖五条件共200次，均可在12次调用内完成。这些是受控脚本结果，不是当前默认混合行为的完成率。
- 集成验证：在临时目录跑通30次脚本pilot、600次脚本demo及160次脚本在线对照，包含数据加工、模型训练、策略读回与离线评价。
- 正式 collection 调度协议通过mock验证；**未调用真实付费模型**。所有临时验证产物均不作为正式研究数据交付。

104项为包含参数化实例的测试数量，不代表104个独立研究实验。脚本的错误行为和Token估算均是人工设计的，不能据此评价真实预警收益。

## 4. 下一步：预算与真实试运行准备

优先完成以下事项，再调用真实模型：

1. 对齐默认12次工具调用、累计30,000输入与输出Token，以及120秒Session端到端截止。目前默认仍为18次工具、24,000 Token和24次模型调用；HTTP单次超时不等于Session时间预算。
2. 明确本次请求可能使累计Token超限的处理边界，时间截止应同时进入执行循环与告警资格判断。
3. 配置准确模型ID、推理参数、价格和总费用B；费用账本应计入无效运行的已知支出并标记未知费用，不能仅汇总分析有效样本。
4. 实现试运行预算触顶、成功/失败、真实故障触发与恢复统计，分别估算30次pilot、600次主采集和160次在线对照费用。
5. 决定并冻结超时/限流的延迟模型。目前故障立即返回，不能声称已测量真实工具等待的节省。
6. 在查看测试结果前记录在线160次、缩减80次或取消的决定。当前入口仅实现160次；缩减和取消决策记录待补。
7. 完成供应商协议验证及30次训练限定pilot；只依据训练数据调整，正式数据独立采集。
