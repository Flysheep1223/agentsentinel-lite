## 本地验证记录

- 自动化测试：21 项通过，覆盖状态与重复写验证、故障恢复、硬预算边界、因果特征、模板切分、干预样本排除、阈值成本选择、缺失用量和 SSE 字节重建。
- 静态检查：`ruff check src tests` 通过。
- 离线工程演示：`data/demo_verified/`，600 个 Session，4,471 条决策前缀，12/4/4 个模板对应 360/120/120 个 Session。
- 独立在线工程验证：`data/demo_verified/online/`，四种策略各 40 个 Session，共 160 个，基础设施无效 Session 为 0。
- 已生成训练 EDA、PR/ROC/校准曲线、停止策略比较图、逐前缀评分表、逐 Session 回放表、JSON 指标和冻结模型。

这里的 Token 是脚本根据消息长度估算的计数，故障和 Agent 的不完善行为也是人工设计的。真实计时会受到线程调度与模型评分的影响，尤其在本地脚本执行极快时，在线和离线耗时分布可能明显变化。上述验证不证明任何停止策略提高了真实任务的效益。

## 下一阶段

1. 在项目 `.env` 填写 OpenAI-compatible 接口、模型名与价格；先验证供应商对工具调用、SSE、用量字段和参数的支持。
2. 进行分阶段试运行：先少量调用验证协议，再覆盖两个工作流和全部故障条件，检查成功/失败比例、可恢复错误与语义失败是否都有足够样本。
3. 根据试运行冻结硬预算、故障强度和延迟模型。当前注入超时立即返回错误；研究真实超时等待的收益前，需要加入可配置等待并重新试运行。
4. 审查任务模板的实际独立性。当前模板以操作组合与完成条件区分，但共用工具和业务政策；后续可增加不同依赖结构，提升泛化评价的难度。
5. 用独立目录正式采集约 600 个真实模型 Session；若价格已配置，先根据试运行估算总采集与在线对照预算。
6. 冻结模型与验证阈值后执行最终测试、消融及正式在线对照。不要用测试结果反复修改本次实验方案。
7. 补充 KNN 评分耗时随样本量变化的实验，以及按相同任务条件配对重采样的在线策略差异置信区间。当前在线结果包含描述统计，模板 Bootstrap 仅用于离线回放。
8. 根据样本与预算决定是否执行故障类型留出、第二模型/配置泛化，再完成项目报告。相关研究的引文核验与文献整理仍属于后续研究工作。

运行命令和指标口径见根目录 [README](../README.md)。所有正式采集和在线对照都需要真实模型配置；本轮未发送任何外部通知，也未调用付费模型接口。
